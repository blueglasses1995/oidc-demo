## OpenID Connectとは

**OpenID Connect (OIDC)** は、OAuth 2.0の上に構築された認証レイヤーです。

- **OAuth 2.0**: 「認可」のためのプロトコル（リソースへのアクセス権限を与える）
- **OpenID Connect**: 「認証」のためのプロトコル（ユーザーが誰であるかを確認する）

簡単に言うと：
- **OAuth**: 「このアプリにあなたの写真へのアクセスを許可しますか?」
- **OIDC**: 「あなたは誰ですか?（ログイン）」

## 登場人物とその役割

OIDCには主に3つの登場人物がいます：

```
┌─────────────────────────────────────────────────────────────────┐
│                    OIDC エコシステム                              │
└─────────────────────────────────────────────────────────────────┘

    ┌──────────────┐
    │   エンドユーザー │  ← 実際のユーザー（あなた）
    │  (Resource    │
    │    Owner)     │
    └───────┬──────┘
            │
            │ ①ブラウザでアクセス
            │
            ↓
    ┌──────────────────────┐
    │   クライアント          │  ← あなたが作るWebアプリ
    │  (Client / RP)        │
    │                       │
    │  【責務】              │
    │  ・ユーザーにサービス提供│
    │  ・認証フローの開始     │
    │  ・トークンの取得・検証 │
    │  ・ユーザー情報の利用   │
    │                       │
    │  【保持データ】         │
    │  ・Client ID          │
    │  ・Client Secret      │
    │  ・アクセストークン     │
    │  ・IDトークン          │
    └───────┬───────────────┘
            │
            │ ②認証リクエスト
            │ ④トークンリクエスト
            │ ⑥ユーザー情報リクエスト
            │
            ↓
    ┌──────────────────────────────────┐
    │  OpenID Provider (OP)            │  ← 認証サーバー
    │  別名: 認証認可サーバー            │     (Google, Auth0など)
    │                                  │
    │  【責務】                         │
    │  ・ユーザー認証（ログイン画面）     │
    │  ・ユーザー同意の取得              │
    │  ・認可コードの発行                │
    │  ・トークンの発行・管理            │
    │  ・ユーザー情報の提供              │
    │                                  │
    │  【保持データ】                    │
    │  ・ユーザーアカウント情報          │
    │  ・クライアント登録情報            │
    │  ・発行済みトークン                │
    │  ・セッション情報                  │
    │                                  │
    │  【主要エンドポイント】             │
    │  ・/authorize (認可エンドポイント)  │
    │  ・/token (トークンエンドポイント)  │
    │  ・/userinfo (ユーザー情報)        │
    │  ・/.well-known/openid-configuration│
    └──────────────────────────────────┘
```

### 詳細な役割説明

#### 1. エンドユーザー (End User / Resource Owner)
- **誰**: 実際にサービスを使う人
- **役割**: 自分の情報へのアクセスを許可するかどうかを決める
- **操作**: ログインボタンをクリック、認証情報を入力、同意する

#### 2. クライアント (Client / Relying Party - RP)
- **誰**: あなたが開発するWebアプリケーション
- **役割**:
  - ユーザーにサービスを提供する
  - OPに認証を依頼する
  - トークンを取得して検証する
  - ユーザー情報を利用してサービスを提供する
- **保持する重要データ**:
  - `client_id`: クライアントを識別するID（公開情報）
  - `client_secret`: クライアントの秘密鍵（絶対に漏らさない！）
  - `access_token`: APIアクセス用のトークン
  - `id_token`: ユーザー認証情報を含むJWT
  - `refresh_token`: アクセストークン更新用

#### 3. OpenID Provider (OP / 認証認可サーバー)
- **誰**: Google, Auth0, Keyc loakなどの認証サービス
- **役割**:
  - ユーザーの認証（本人確認）
  - ユーザーからの同意取得
  - トークンの発行と管理
  - ユーザー情報の提供
- **保持する重要データ**:
  - ユーザーのアカウント情報（メール、パスワードハッシュなど）
  - 登録されたクライアントの情報
  - 発行済みトークンとその有効期限
  - セッション情報
- **主要エンドポイント**:
  - **Authorization Endpoint** (`/authorize`): 認証・認可のスタート地点
  - **Token Endpoint** (`/token`): トークンの発行
  - **UserInfo Endpoint** (`/userinfo`): ユーザー情報の取得
  - **Discovery Endpoint** (`/.well-known/openid-configuration`): OPの設定情報

## データフローの理解

OIDCの最も一般的なフロー「**Authorization Code Flow**」を図解します：

```
エンドユーザー          クライアント(RP)           OpenID Provider(OP)
    │                      │                          │
    │ ①アプリにアクセス     │                          │
    ├─────────────────────→│                          │
    │                      │                          │
    │                      │ ②認証リクエスト           │
    │                      │  (redirect to OP)        │
    │                      ├─────────────────────────→│
    │                      │  GET /authorize?         │
    │←─────────────────────┤    response_type=code    │
    │  ③ログイン画面表示    │    client_id=xxx         │
    │                      │    redirect_uri=xxx      │
    │                      │    scope=openid profile  │
    │                      │                          │
    │ ④ユーザー名/パスワード入力                       │
    ├────────────────────────────────────────────────→│
    │                      │                          │
    │                      │                          │ ⑤認証・検証
    │                      │                          │
    │ ⑥同意画面表示         │                          │
    │←─────────────────────────────────────────────────┤
    │                      │                          │
    │ ⑦「許可する」クリック │                          │
    ├────────────────────────────────────────────────→│
    │                      │                          │
    │                      │  ⑧認可コード発行          │
    │                      │←─────────────────────────┤
    │←─────────────────────┤  redirect with code      │
    │ (redirect_uriへ)     │                          │
    │                      │                          │
    │                      │  ⑨トークンリクエスト      │
    │                      ├─────────────────────────→│
    │                      │  POST /token             │
    │                      │    grant_type=authorization_code│
    │                      │    code=xxx              │
    │                      │    client_id=xxx         │
    │                      │    client_secret=xxx     │
    │                      │                          │
    │                      │  ⑩トークンレスポンス      │
    │                      │←─────────────────────────┤
    │                      │  {                       │
    │                      │    access_token: "...",  │
    │                      │    id_token: "...",      │
    │                      │    refresh_token: "..."  │
    │                      │  }                       │
    │                      │                          │
    │                      │ ⑪IDトークン検証           │
    │                      │  (JWT署名確認)           │
    │                      │                          │
    │                      │ ⑫ユーザー情報リクエスト    │
    │                      ├─────────────────────────→│
    │                      │  GET /userinfo           │
    │                      │  Authorization: Bearer token│
    │                      │                          │
    │                      │ ⑬ユーザー情報レスポンス    │
    │                      │←─────────────────────────┤
    │                      │  {                       │
    │                      │    sub: "123",           │
    │                      │    name: "太郎",         │
    │                      │    email: "..."          │
    │                      │  }                       │
    │                      │                          │
    │ ⑭ログイン完了         │                          │
    │←─────────────────────┤                          │
    │  (アプリのページ表示)  │                          │
    │                      │                          │
```

### 各ステップの詳細説明

1. **ユーザーがアプリにアクセス**: ブラウザでアプリを開く
2. **認証リクエスト**: クライアントがOPの認証ページにリダイレクト
3. **ログイン画面表示**: OPがユーザーにログインフォームを表示
4. **認証情報入力**: ユーザーがメール/パスワードを入力
5. **認証・検証**: OPがユーザー情報を確認
6. **同意画面表示**: 「このアプリにあなたの情報へのアクセスを許可しますか?」
7. **同意**: ユーザーが「許可する」をクリック
8. **認可コード発行**: OPが一時的なコードを発行してクライアントにリダイレクト
9. **トークンリクエスト**: クライアントが認可コードをトークンに交換（サーバー間通信）
10. **トークン発行**: OPがaccess_token、id_token、refresh_tokenを発行
11. **IDトークン検証**: クライアントがJWT署名を確認してトークンの正当性を検証
12. **ユーザー情報リクエスト**: アクセストークンを使ってユーザー情報を取得
13. **ユーザー情報取得**: 名前、メールなどの情報を取得
14. **ログイン完了**: ユーザーにアプリの画面を表示

## 重要なトークンの種類

### 1. ID Token (IDトークン)
```json
{
  "iss": "https://op.example.com",          // 発行者
  "sub": "24400320",                        // ユーザーの一意なID
  "aud": "s6BhdRkqt3",                      // クライアントID
  "exp": 1311281970,                        // 有効期限
  "iat": 1311280970,                        // 発行時刻
  "name": "山田太郎",                        // ユーザー名
  "email": "yamada@example.com"             // メールアドレス
}
```
- **形式**: JWT (JSON Web Token)
- **目的**: ユーザーの認証情報を含む
- **検証**: クライアントが署名を検証して信頼性を確認

### 2. Access Token (アクセストークン)
```
eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiI...
```
- **目的**: APIアクセスのための権限証明
- **使い方**: `Authorization: Bearer <token>` ヘッダーに付与
- **有効期限**: 短い（通常15分〜1時間）

### 3. Refresh Token (リフレッシュトークン)
```
8xLOxBtZp8
```
- **目的**: アクセストークンの更新
- **有効期限**: 長い（数日〜数ヶ月）
- **セキュリティ**: 絶対に安全に保管
